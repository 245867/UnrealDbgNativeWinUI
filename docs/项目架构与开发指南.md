# UnrealDbg 项目架构与开发指南

> 本文档供后续开发维护使用。内容基于 2026-09-21 清理后的目录状态编写。

---

## 1. 项目概述

UnrealDbg 是一款基于 Intel VT-x 硬件虚拟化技术的 Windows 内核调试器。它通过在 Hypervisor 层（Ring -1）拦截调试相关内核函数，实现对目标进程的透明调试，绕过传统反调试手段。

**核心特性：**
- **VT 技术**：利用 Intel VMX/EPT 实现硬件级调试断点和事件拦截
- **原生 WinUI 3 前端**：C++ 原生 XAML 界面，暗黑主题，单页操作，无 WebView
- **Windows 版本精确适配**：按 Build + UBR 匹配 Win10/Win11 桥接驱动，未知版本拒绝加载
- **驱动事务状态机**：分阶段加载，失败可追溯
- **符号缓存**：PDB/EXP/LIB 调试符号管理，版本失效自动重验
- **多调试器支持**：可注册多个外部调试器（x64dbg 等）并通过前端启动

## 2. 系统架构

### 2.1 整体分层

```
┌──────────────────────────────────────────────┐
│         UnrealDbgNativeWinUI.exe               │  ← 前端 (用户态)
│  WinUI 3 / XAML / 暗黑主题                     │
│  WinUiMain.cpp → WinUiController.cpp           │
├──────────────────────────────────────────────┤
│         UnrealDbgDll.dll                       │  ← 后端 (用户态)
│  初始化驱动 / 管理符号 / 启动目标进程 / TL选项  │
├──────────────────────────────────────────────┤
│         Hook64.dll                             │  ← 注入 DLL (目标进程内)
│  Hook 调试API / 通道通信 / 断点管理            │
├──────────────────────────────────────────────┤
│  DbgkSysWin10.sys / DbgkSysWin11.sys          │  ← 桥接驱动 (内核态)
│  拦截 Dbgk 系统调用 / 调试事件分发             │
├──────────────────────────────────────────────┤
│         VT_Driver.sys                          │  ← VT 核心驱动 (内核态)
│  VMX 初始化 / EPT 映射 / VM-Exit 处理 / VMCALL  │
└──────────────────────────────────────────────┘
```

### 2.2 驱动事务状态机

驱动加载遵循严格的事务状态机，任何阶段失败都会记录阶段名、Win32 错误码、系统原文、原因和解决方案：

```
精确版本检查 → 服务身份/二进制路径检查 → VT_Driver 核心就绪
→ Win10/Win11 桥接驱动就绪 → 打开 \\.\UnrealDbg → IOCTL 符号握手 → Ready
```

- 桥接阶段失败时仅补偿本次创建的 `UnrealDevice`
- VT 核心可能已进入 VMX 状态，程序不会未经验证强制卸载，而是要求重启恢复
- 不通过关闭 HVCI / 安全启动 / 永久启用 TESTSIGNING 来规避错误 577

### 2.3 IOCTL 通信协议

前端与驱动通过 DeviceIoControl 通信，定义在 `Common/Shared/IOCTLs.h`：

| IOCTL | 功能 | V1 (0x800~0x80B) | V2 (0x900~0x90B) |
|-------|------|:-:|:-:|
| LOAD_SYMBOLS_TABLE | 加载符号表 | 0x800 | 0x900 |
| LOAD_DEBUGGER_STATE | 加载调试器状态 | 0x801 | 0x901 |
| LOAD_PROTECT_OBJ_DATA | 加载保护对象 | 0x802 | 0x902 |
| LOAD_DEBUGGER_DATA | 加载调试器数据 | 0x803 | 0x903 |
| CREATE_REMOTE_THREAD | 创建远程线程 | 0x804 | 0x904 |
| SET_HARDWARE_BREAKPOINT | 设置硬件断点 | 0x805 | 0x905 |
| GET_PROCESS_INFO | 获取进程信息 | 0x806 | 0x906 |
| TL_BLOCK_RESUME_THREAD | 阻塞恢复线程 | 0x807 | 0x907 |
| DEL_HARDWARE_BREAKPOINT | 删硬件断点 | 0x808 | 0x908 |
| SET_SOFTWARE_BREAKPOINT | 设软件断点 | 0x809 | 0x909 |
| DEL_SOFTWARE_BREAKPOINT | 删软件断点 | 0x80A | 0x90A |
| READ_SOFTWARE_BREAKPOINT | 读软件断点 | 0x80B | 0x90B |

V2 要求显式 read/write 设备句柄权限（`UNREALDBG_IOCTL_SECURE_ACCESS`），V1 保留兼容旧客户端。

## 4. 模块详解

### 4.1 VT_Driver — VT 核心驱动

**路径：** `VT_Driver/`
**输出：** `VT_Driver.sys`
**技术：** Intel VMX / EPT / VMCS

核心文件：

| 文件 | 职责 |
|------|------|
| `Driver.cpp` | 驱动入口，IRP 分发，设备创建 |
| `vmm.cpp` / `vmm.h` | 虚拟机监视器核心，VM-Entry/Exit 循环 |
| `vmcs.cpp` / `vmcs.h` | VMCS 字段配置（_guest/host 状态_） |
| `vmexit_handler.cpp` | VM-Exit 原因分发处理器 |
| `EPT.cpp` / `EPT.h` | 扩展页表，内存隐藏/断点 |
| `vmcall_handler.cpp` | VMCALL 超调用处理（用户态→Hypervisor 通信） |
| `poolmanager.cpp` | 内核池内存管理 |
| `spinlock.cpp` | 自旋锁同步 |
| `gdt.cpp` | GDT/LDT 处理 |
| `hypervisor_gateway.cpp` | Hypervisor 网关接口 |
| `ASM/` | 汇编入口（VMX 启动/退出） |
| `Init/` | 初始化序列 |

关键头文件：`cpuid.h`, `crx.h` (控制寄存器), `drx.h` (调试寄存器), `msr.h`, `vmx.h`, `mtrr.h`, `exception.h`, `segment.h`

### 4.2 DbgkSysWin10 / DbgkSysWin11 — 桥接驱动

**路径：** `DbgkSysWin10/` (Win10 22H2), `DbgkSysWin11/` (Win11 21H2~25H2)
**输出：** `DbgkSysWin10.sys` / `DbgkSysWin11.sys`

两个驱动结构对称，按目标 Windows 版本的内核结构体偏移差异分别维护：

| 子目录 | 职责 |
|--------|------|
| `Asm/` | 汇编桩 |
| `DbgkApi/` | Dbgk 系统调用拦截 |
| `DebugBreak/` | 调试断点处理 |
| `Encrypt/` | 内核态 Blowfish 加密 |
| `Hooks/` | 内核函数 Hook |
| `Hvm/` | Hypervisor 接口 |
| `Init/` | 初始化 |
| `List/` | 链表管理 |
| `Log/` | 日志输出（UDBG-UTF8/1 协议） |
| `Memory/` | 内存操作 |
| `ntos/` | NT 内核结构体定义 |
| `Process/` | 进程信息 |
| `Protect/` | 保护对象 |

### 4.3 Hook — 注入 DLL

**路径：** `Hook/`
**输出：** `Hook64.dll`

注入到目标进程，拦截调试 API 调用并通过通道与前端通信：

| 子目录 | 职责 |
|--------|------|
| `Channels/` | 前后端通信通道 |
| `DebugBreak/` | 断点逻辑 |
| `DebugEvent/` | 调试事件处理 |
| `HookCallSet/` | Hook 函数集合 |
| `Inject/` | 注入辅助 |
| `Log/` | 日志 |
| `vmx/` | VMX 交互 |

### 4.4 Loader — 驱动加载器

**路径：** `Loader/`
**输出：** `Loader.exe`

负责加载/卸载 VT_Driver.sys 和桥接驱动。通过服务控制管理器（SCM）创建内核驱动服务，支持事务性加载和回滚。

### 4.5 UnrealDbgDll — 后端 DLL

**路径：** `UnrealDbgDll/`
**输出：** `UnrealDbgDll.dll`

用户态后端，被前端加载。核心职责：
- 通过 `Initialize(key)` 初始化（密钥脱敏，不写入日志）
- 管理符号加载（通过 IOCTL 下发给驱动）
- 启动目标进程并注入 Hook64.dll
- TL（反调试）选项控制（GetTickCount hook、阻塞 ResumeThread）
- `Shutdown()` 有序关闭

导出函数（见 `dllexport.def`）：`Initialize`, `StartProcess`, `GetFileVersion`, `BlockResumeThread`, `Shutdown`

### 4.6 UnrealDbgNative — WinUI 3 前端

**路径：** `UnrealDbgNative/`
**输出：** `UnrealDbgNativeWinUI.exe`（在 `x64/WinUI/Release/`）

| 文件 | 职责 |
|------|------|
| `WinUiMain.cpp` | WinUI 入口，XAML 界面构建（101KB，主文件） |
| `WinUiController.cpp/.h` | 后端控制器，管理 DLL 加载/驱动初始化/符号/调试器列表/TL 选项 |
| `Core.cpp/.h` | 核心工具：日志、错误解释、路径解析、权限检查、WMI 查询、诊断快照 |
| `LogPanel.cpp/.h` | 底部实时日志面板（分级着色：Debug 蓝/Info 绿/Error 红） |
| `UiComponents.cpp/.h` | 通用 UI 组件 |
| `UiTheme.h` | 暗黑主题颜色/字体定义 |
| `SymbolCache.cpp/.h` | 符号缓存管理（PDB/EXP/LIB 版本校验） |
| `WinRtAbiCompat.h` | C++/WinRT ABI 兼容层（处理 GetCurrentTime 宏冲突） |
| `UnrealDbgNativeWinUI.vcxproj` | WinUI 工程文件 |
| `RestoreWinUiPackages.ps1` | NuGet 包恢复脚本 |

**前端布局：** 单页状态概览 → 调试器列表 → TL 选项 → 底部全局日志

### 4.7 Common — 共享库

## 5. 编译与运行

### 5.1 编译环境

- **IDE：** Visual Studio 2019 + WDK
- **配置：** x64 Release（推荐）或 x64 Debug
- **解决方案：** `UnrealDbg.sln`

### 5.2 WinUI 前端构建

首次构建需要恢复 NuGet 包（已删除 `_artifacts/winui_packages`，需手动恢复）：

```powershell
powershell -ExecutionPolicy Bypass -File UnrealDbgNative\RestoreWinUiPackages.ps1
```

构建产物放在 `x64\WinUI\Debug` 或 `x64\WinUI\Release`。运行时 DLL、驱动集中在 `bin` 子目录。

### 5.3 运行前置条件

1. 安装 Windows App Runtime 1.8 x64
2. 以管理员权限运行
3. 测试证书导入"本地计算机\受信任的根证书颁发机构"和"受信任的发布者"
4. 隔离 VM 中可启用 TESTSIGNING（正式发布不使用此方式）

### 5.4 运行

```bat
# 直接运行
x64\WinUI\Release\UnrealDbgNativeWinUI.exe

# 或使用批处理
启动GUI.bat
```

程序自动解析 `bin/` 和 `Config/` 目录，兼容旧版根目录布局。

## 9. 安全注意事项

### 9.1 ★ F3 目录保护

`x64/Release/` 下的 **F3**、**F3_VT9_15**、**F3_VT_9_16** 目录和 `F3(新).rar` 为受保护资产：

- **禁止删除、修改、上传、外传**
- 清理操作已验证这些目录完整保留

### 9.2 签名策略

- **开发测试**：隔离快照 VM + 测试证书，导入受信任根和发布者
- **正式发布**：Microsoft 认可的内核驱动签名流程（硬件开发者中心/Attestation 或 WHQL）
- **禁止**通过关闭 HVCI/安全启动或永久启用 TESTSIGNING 规避错误 577

### 9.3 后端密钥

后端 DLL 初始化密钥始终脱敏，不会写入任何日志或诊断包。
